# 하자처리 대시보드 — 배포 키트 사용법

## 파일 구성

| 파일 | 역할 | 언제 손대나 |
|---|---|---|
| `index.html` | 대시보드 본체 (P1~P5 + 접근성·CSP·PII마스킹 반영 최종본) | 기능 수정 시 |
| `update_csp_hash.py` | JS 수정 후 CSP 해시 자동 갱신 | **index.html의 JS를 고칠 때마다 반드시** |
| `database.rules.json` | Firebase RTDB 보안 규칙 (email 위조 차단 강화판) | 권한 정책 변경 시 |
| `firebase.json` | Firebase CLI 설정 (규칙 경로 + 에뮬레이터 포트) | 거의 안 건드림 |
| `tests/database.rules.test.mjs` | 보안 규칙 단위테스트 21케이스 | 규칙 수정 시 실행 |
| `package.json` | 테스트 의존성 + 단축 명령 | 최초 1회 `npm install` |

## 1. 대시보드 배포 (평소 쓰는 흐름)

리포지토리 폴더에 `index.html`을 넣고, 같은 폴더에 `PretendardVariable.woff2`가
있는지 확인한 뒤(기존과 동일) GitHub Pages로 푸시하면 끝.

```
리포지토리/
├─ index.html                  ← 이 키트의 파일로 교체
├─ PretendardVariable.woff2    ← 기존 파일 그대로 (없으면 폰트만 기본체로 뜸)
├─ update_csp_hash.py
├─ database.rules.json
├─ firebase.json
├─ package.json
└─ tests/database.rules.test.mjs
```

## 2. JS를 수정했을 때 — 해시 갱신 (제일 중요)

`index.html`의 `<script>` 본문을 한 글자라도 고치면 CSP 해시가 어긋나
**화면 전체가 하얗게 차단**됩니다. 수정 후 커밋 전에 딱 한 줄:

```bash
python3 update_csp_hash.py
```

- `... 교체 완료`가 뜨면 해시가 갱신된 것 → 커밋하면 됨
- `변경 없음 (해시 일치)`가 뜨면 JS를 안 건드렸다는 뜻 → 그냥 커밋
- npm이 설치돼 있으면 `npm run hash`도 같은 동작

## 3. 배포 후 확인 (2분 체크리스트)

1. 주소 뒤에 `?selftest=1` 붙여 접속 → 전부 초록(PASS)인지 확인
   (날짜 정규화·집계·**PII 마스킹 7케이스** 포함)
2. 일반 접속해서 로그인 → 차트·Pretendard 폰트·reCAPTCHA 배지가 보이는지
   (CSP 강화 영향권 — 하나라도 안 뜨면 브라우저 콘솔의 CSP 오류를 캡처해서 다음 세션에 공유)
3. Tab 키만으로 사이드바 메뉴 → 현장 목록 → 표 정렬 헤더가 순서대로
   파란 테두리로 잡히고 Enter로 동작하는지

## 4. 보안 규칙 배포

규칙은 대시보드 배포와 **별개**입니다. 둘 중 하나로:

**방법 A — 콘솔 (제일 간단):**
Firebase 콘솔 → Realtime Database → 규칙 탭 → `database.rules.json` 내용
전체를 붙여넣고 게시. (주석 포함 그대로 붙여도 됩니다)

**방법 B — CLI:**
```bash
npx firebase deploy --only database --project report-c29a1
```

## 5. 규칙 테스트 실행 (규칙을 고쳤을 때만)

로컬 PC에서 최초 1회 준비:
```bash
npm install          # 테스트 의존성 설치 (Java 11+ 필요 — 에뮬레이터 요구사항)
```

실행:
```bash
npm run test:rules
```
25개 케이스가 전부 pass면 배포해도 안전합니다. 케이스: 자기승격 차단,
blocked 자가해제 차단, 타인 이메일 위조 차단, viewer의 report 쓰기 거부,
plans 필드 화이트리스트·글자수 한도, 사외 도메인 차단 등.

## 6. 이번 버전에서 달라진 동작 (운영자가 알아야 할 것)

- **게시(등록) 버튼**: 이제 화면 렌더를 기다리지 않고 즉시 집계를 산출하며,
  게시와 함께 로컬 처리계획·분석의견이 Firebase에 자동 시드됩니다.
- **실시간 협업**: 현재 열어둔 현장만 실시간 동기화됩니다. 다른 현장의
  동료 수정분은 그 현장을 여는 순간 반영됩니다(트래픽 대폭 절감).
- **AI 분석**: Gemini로 나가는 접수내용에서 전화번호·이메일·인명(님/씨)이
  자동 마스킹됩니다. 동·호수는 원인분석용으로 그대로 전송됩니다.
- **통합 검색**: 상단 검색창에서 동·호·공종·접수내용으로 전 현장을 검색합니다.
  "101동 1203호"처럼 입력하면 해당 세대의 접수 건이 처리 상태와 함께 뜨고,
  행을 클릭하면 그 현장 패널로 이동합니다. (원본 데이터가 있는 편집자 화면 전용)
- **뷰어 기준월 선택**: 게시된 달이 2개 이상이면 상단 기준월 칩 옆에 선택기가
  나타나 과거 월간보고를 그대로 열람할 수 있습니다. 게시 시 자동으로 목록에 추가됩니다.
- **전월 계획 불러오기**: 현장 패널의 '장기미처리 상위 5개 공종' 카드에서 버튼 한 번으로
  전월 처리계획을 이번 달 빈 칸에만 복사합니다(이미 입력한 칸은 보존, 협업자에게 즉시 동기화).
- **주소 공유**: 화면 주소가 `#site/현장ID` 형태로 유지되어 새로고침해도 보던 화면이
  유지되고, 링크를 복사해 메신저로 "이 현장 봐봐"를 공유할 수 있습니다.
- **분석의견 월별 아카이브**: 분석의견이 기준월별로 저장됩니다. 기준월을 바꾸면
  그 달의 분석의견이 표시되고, AI 재생성은 현재 기준월에만 기록되어 과거 월 분석이
  보존됩니다. 기존 분석의견(월 정보 없음)은 최초 접속 시 현재 기준월로 자동 귀속됩니다.
- **기준월**: 매월 1일 이른 아침 접속 시 기준월이 한 달 밀리던 문제 해결.
- **키보드**: 마우스 없이 Tab+Enter로 내비게이션·표 정렬이 가능합니다.

## 7. 문제 생겼을 때

| 증상 | 원인 | 조치 |
|---|---|---|
| 화면이 하얗고 아무것도 안 뜸 | JS 수정 후 해시 미갱신 | `python3 update_csp_hash.py` 후 재배포 |
| 폰트/배지/이미지가 안 뜸 | CSP 차단 | 콘솔(F12)의 CSP 오류 도메인 확인 후 공유 |
| 뷰어에게 처리계획이 비어 보임 | 게시 전 상태 | 편집자가 게시 1회 실행(자동 시드됨) |
| 규칙 배포 후 접근 불가 | 규칙 오타/회귀 | `npm run test:rules`로 회귀 확인 |
