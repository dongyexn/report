# 하자처리 현황 대시보드

아파트 현장의 하자보수 접수·처리 현황을 한곳에 모아, 팀 전체가 같은 화면으로 보는 웹 대시보드입니다.

- 주소: https://dongyexn.github.io/report/
- 회사 이메일(`@hdec.co.kr`)로 가입하면 누구나 열람할 수 있습니다.

> 이 문서는 **1~5장이 모든 팀원용**, **6장부터가 운영·개발 담당자용**입니다.
> 처음 쓰신다면 1장만 읽어도 충분합니다.

---

## 1. 처음 오셨다면 (5분 안내)

### 1) 로그인

접속 → 회사 이메일로 가입 → 메일로 온 인증 링크 클릭 → 로그인.
가입하면 **열람 권한이 자동으로 부여**됩니다. 따로 신청할 것은 없습니다.

### 2) 화면이 어떻게 생겼나

![화면 구성](docs/guide-layout.png)

| | 무엇 |
|---|---|
| **1** | **팀 선택** — 여러 팀을 볼 수 있는 경우에만 바뀝니다. |
| **2** | **대시보드** — 팀 전체 합계 화면으로 이동. |
| **3** | **현장 목록** — 권역별로 묶여 있습니다. 이름을 누르면 그 현장 화면으로. |
| **4** | **기준월** — 지금 보고 있는 집계의 기준이 되는 달. |
| **5** | **사용 안내** — 이 문서를 여는 버튼. |
| **6** | **인쇄** — 지금 화면을 그대로 인쇄하거나 PDF로 저장. |

사이드바는 접어둘 수 있고, 접으면 아이콘만 남습니다(아이콘에 마우스를 올리면 이름이 뜹니다).
화면이 좁은 휴대폰·태블릿에서는 사이드바가 숨겨지고 왼쪽 위 메뉴 버튼으로 열립니다.

### 3) 대시보드 — 팀 전체 요약

로그인하면 처음 보이는 화면입니다. 우리 팀 전 현장을 합친 숫자입니다.

![KPI 카드](docs/guide-kpi.png)

- 맨 위 **카드 5개**가 요약입니다: 관리대상현장 · 전체 접수 · 처리 완료 · 미처리 · 장기미처리(**1**).
- 미처리·장기미처리 카드의 **「목록 보기」**(**2**)를 누르면 그 숫자를 이루는 **실제 목록**이 열립니다.
- 그 아래로 주차별 추이 차트 → 전월 대비 실적 → 주요 이슈 → 월별·현장별 현황 표가 이어집니다.
- **주요 이슈 카드를 누르면 펼쳐져서** 현장별·공종별로 쪼갠 상세가 나옵니다.
  다시 누르거나 `Esc` 키를 누르면 접힙니다.

### 4) 현장 하나 열어보기

사이드바에서 현장을 누르면 그 현장 화면이 열리고, 위쪽에 탭이 있습니다.

![현장 화면 탭](docs/guide-tabs.png)

| | 탭 | 여기서 보는 것 |
|---|---|---|
| **1** | **종합** | 그 현장의 요약 숫자, 주차별 추이, 공종별 분포, 종합 분석 의견 |
| **2** | **장기미처리** | 30일을 넘긴 건들 — 비율 현황 바, 상위 공종, 공종별 전체 현황(처리계획 칸 포함) |
| **3** | **공가세대** | 빈 세대 관련 현황 (상가가 있는 현장은 **공가상가** 탭도 함께) |
| **4** | **상세 현황** | 월별·주차별 상세 표 |

### 5) 이것만 알면 편합니다

- **마우스를 올려보세요.** 숫자·증감 배지·막대에 커서를 올리면 설명이 뜹니다(전월 → 금월 비교 등).
- **오른쪽 버튼을 눌러보세요.** 표·목록·차트 위에서 우클릭하면 복사·목록 보기 메뉴가 나옵니다.
  표를 복사해 엑셀이나 메일에 `Ctrl+V`로 그대로 붙여넣을 수 있습니다.
- **인쇄 버튼**으로 지금 화면을 그대로 인쇄하거나 PDF로 저장할 수 있습니다(보고용).
- 오른쪽 위 **`?` 버튼**을 누르면 이 안내서가 열립니다(왼쪽 목차에서 원하는 장으로 이동).
  처음 로그인하면 한 번은 자동으로 열립니다.

## 2. 숫자 읽는 법

화면의 모든 숫자는 **기준월 말일 시점**으로 계산됩니다. 오늘 날짜 기준이 아닙니다.
예를 들어 기준월이 2026-06이면 "6월 30일까지 어떤 상태였는가"를 보여줍니다.

| 용어 | 뜻 |
|---|---|
| **기준월** | 집계의 기준이 되는 달. 화면 오른쪽 위에 표시됩니다. 월간 보고가 "전월 말일까지" 기준이라 보통 지난달입니다. |
| **전체 접수** | 기준월 말일까지 접수된 하자 건수(누계). |
| **처리 완료 / 미처리** | 기준월 말일 시점에 처리가 끝난 건 / 아직 남은 건. |
| **장기미처리(30일)** | 접수 후 30일이 지나도록 처리되지 않은 건. 오래될수록 문제가 되는 지표입니다. |
| **지연구간** | 미처리 건을 경과일로 나눈 것 — **60일 이상 / 30~59일 / 30일 미만**. 차트와 막대의 색이 이 구간입니다. |
| **중대하자 의심** | 누수·엘리베이터·퇴거 등 파급이 큰 건을 넓게 뽑은 후보. 최종 판단은 분석 의견에서 정리됩니다. |
| **공가세대 / 상가** | 아직 입주하지 않은 세대·상가 관련 건. 출입이 어려워 별도로 관리합니다. |
| **인수 전 현장** | 아직 인수 전인 현장. **팀 합계에는 빠지고**, 현장 화면에서는 따로 볼 수 있습니다. |
| **처리계획** | 공종별로 "어떻게 처리할지" 적어두는 칸(장기미처리 탭). |
| **분석 의견** | 그 달의 현황을 글로 정리한 것. 현장 화면 아래쪽에 있습니다. |
| **게시본** | 담당자가 등록해 팀 전체가 함께 보는 그 달의 집계. 여러분이 보는 화면이 이것입니다. |
| **스냅샷** | 게시본을 그대로 담은 HTML 파일 1개. 로그인 없이 열어보는 보관·공유용입니다. |

## 3. 목록 자세히 보기

미처리·장기미처리 카드나 표의 링크를 누르면 **목록 창**이 열립니다. 여기서 할 수 있는 것들입니다.

![목록 창](docs/guide-list.png)

- **검색**(**1**) — 창 위쪽 검색칸에 동·호·공종·접수내용을 입력하면 바로 걸러집니다.
- **표 복사 / 엑셀**(**2**) — 지금 보이는 표를 클립보드로 복사하거나 엑셀 파일로 내려받습니다.
- **피벗**(**3**) — 행·열·값을 조합한 교차표로 바꿉니다(자세한 사용법은 아래).
- **지연구간 칩**(**4**) — 60일 이상 등으로 빠르게 좁히기.
- **정렬·필터** — 열 제목을 누르면 정렬, 열 제목을 **우클릭**하면 값 목록에서 골라 필터·열 숨기기.
  열 경계를 끌면 너비가 바뀝니다.
- **피벗 자세히** — `피벗` 버튼을 누르면 행·열·값을 조합한 교차표가 됩니다.
  팀 전체 목록은 기본이 행=현장, 열=공종, 값=건수입니다. 칩을 끌어 순서를 바꾸고,
  `%` 버튼으로 비중을 함께 볼 수 있습니다. 피벗 칸을 **우클릭**하면 그 조합의 원본 목록으로 들어갑니다.
- 닫기는 `Esc` 키로도 됩니다.

### 우클릭으로 할 수 있는 것

| 어디서 | 나오는 메뉴 |
|---|---|
| 사이드바 현장 | 현장 화면 열기 · 미처리/장기미처리 목록 |
| 대시보드 현장별 표의 행 | 현장 화면 · 목록 바로가기 · 셀 값/표 복사 |
| 현장 공종 표의 행 | 그 공종만 골라낸 목록 · 표 복사 |
| 일반 표(월별·상세 등) | 표 복사 · 셀 값 복사 |
| 목록 창의 칸 | 이 값으로 필터 · 제외 · 값 복사 |
| 목록 창의 열 제목 | 필터 · 열 숨기기 · 숨긴 열 다시 보기 |
| 피벗 칸 | 해당 목록 보기 · 값 복사 |
| 차트 | 이미지 복사(보고서 붙여넣기) · PNG 저장 |
| 분석 의견·주요 이슈 | 텍스트 복사 |

### 단축키

`Esc` 창 닫기 · `?` 단축키 도움말 · 목록 창에서 `Ctrl+F` 또는 `/` 검색.
(입력 중에는 단축키가 동작하지 않습니다.)

## 4. 같이 작성하기 — 처리계획·분석 의견

**열람 권한만 있어도 처리계획과 분석 의견은 직접 쓸 수 있습니다.** 팀 협업용이라 열어두었습니다.

- **처리계획** — 현장 화면 > 장기미처리 탭의 공종별 표 오른쪽 칸에 바로 입력합니다.
- **분석 의견** — 현장 화면 > 종합 탭 아래쪽 「종합 분석 의견」.
- 입력한 내용은 **자동 저장되고 팀 전체에 실시간 공유**됩니다. 저장 버튼은 없습니다.
- 장기미처리 탭의 **「전월 계획 불러오기」** 버튼을 누르면 지난달에 쓴 계획이 이번 달 빈 칸에만
  채워집니다(이미 쓴 칸은 건드리지 않습니다). 매달 처음부터 타이핑하지 않아도 됩니다.

반대로 **업로드·게시·현장 관리·계정 관리는 담당자(편집자)만** 할 수 있습니다.

## 5. 자주 묻는 질문

**Q. 숫자가 어제와 다릅니다.**
담당자가 새 엑셀로 다시 게시하면 바뀝니다. 화면은 게시된 최신본을 실시간으로 따라가며,
보고 있는 중에 갱신되면 **「게시본이 갱신되었습니다」** 안내가 잠깐 뜹니다.

**Q. 접수내용에 `***`나 `○○님`이 보입니다.**
입주민 개인정보(전화·이메일·이름)는 가려서 공유합니다. 정상입니다.

**Q. 기준월을 바꾸고 싶습니다.**
지난달 것도 게시되어 있으면 오른쪽 위에 **월 선택 상자**가 나타납니다. 거기서 고르면 됩니다.
게시된 달이 하나뿐이면 선택 상자 없이 기준월만 표시됩니다.
열람 중에 새로운 달이 등록되면 **「새로 등록되었습니다 · 열기」** 안내가 떠서 바로 넘어갈 수 있습니다.

**Q. 어떤 건 눌러도 수정이 안 됩니다.**
현장 정보·업로드·게시는 담당자 전용입니다. 처리계획·분석 의견은 누구나 쓸 수 있습니다.

**Q. 스냅샷 파일(.html)을 받았습니다.**
더블클릭하면 브라우저에서 열립니다. 로그인 없이 볼 수 있고 내용은 만든 시점으로 고정입니다.
여러 달을 담아 만든 파일이면 오른쪽 위에서 **기준월을 바꿔가며** 볼 수 있습니다.
차트를 그리는 데 인터넷 연결이 필요합니다(사내망에서 막히면 안내 문구가 뜹니다).

**Q. 로딩 화면에서 멈춥니다.**
잠시 기다린 뒤 `Ctrl+F5`로 새로고침해 보시고, 계속되면 담당자에게 알려주세요.

## 6. 권한과 계정

| 역할 | 할 수 있는 것 | 부여 방법 |
|---|---|---|
| `viewer` | 게시본 열람 + **처리계획·분석 의견 작성** | 회사 이메일로 가입하면 자동 |
| `editor` | 위 전부 + 엑셀 업로드·게시·현장/권역 관리·계정 관리 | 기존 편집자가 설정 > 계정 관리에서 변경 |
| `blocked` | 접근 차단 | 편집자가 지정 |

가입은 `@hdec.co.kr` 이메일 + 메일 인증이 필수입니다. 보안 규칙상 **자기 자신에게 편집자
권한을 줄 수 없습니다**(권한 상승 차단). 최초 관리자 1명만 Firebase 콘솔에서
`users/{uid}/role = "editor"`를 한 번 수동 설정합니다.

## 7. 편집자 — 월간 운영 루틴

1. HCS에서 「전체 하자 목록」 엑셀 다운로드(전 현장 통합본).
2. 업로드 → 현장별 자동 분배·파싱 → 업로드 요약(현장·건수·기간)을 원본과 대조.
   필수 컬럼(접수일·처리상태·공종)이 없으면 차단되고, 그 외 표준 컬럼이 빠져 있으면
   경고창이 뜹니다(HCS 컬럼명 변경 신호 — 원본 헤더 확인 후 진행 여부 결정).
3. **기준월 확인** — 자동으로 전월이 잡힙니다(엑셀에 당월 접수분이 섞여도 전월 상한).
4. 대시보드·현장 화면 검토 → 장기미처리 표에 **처리계획** 작성(「전월 계획 불러오기」 버튼 활용) →
   월별 **분석 의견** 작성.
5. 설정 > 사내 게시 > **등록**. 등록이 끝나면 안내에 **「스냅샷 저장」** 버튼이 뜨므로 그 자리에서
   백업을 남길 수 있습니다(원본은 마스터 PC에만 있으므로 백업이 유일한 안전장치입니다).
   기준월보다 미래인 게시월이 남아 있으면 삭제 제안이 대신 뜹니다 — 잘못 게시된 월이면 반드시
   삭제하세요(팀원의 월 선택 상자에 계속 노출됩니다).
6. (권장) 설정 > **스냅샷 내보내기**로 백업 1부 보관 — 포함할 기준월을 골라 여러 달을 한 파일에
   담을 수 있습니다(9장).
7. 설정 > **뷰어 시점으로 보기**로 팀원에게 보이는 화면을 최종 확인. `F5`로 편집 모드 복귀.

## 8. AI 분석 (Gemini)

- 설정 > AI 분석에 **개인 Gemini API 키**를 입력하면 현장 화면의 "AI 분석 생성"과
  대시보드 주요 이슈 재작성이 활성화됩니다. 키는 그 PC의 브라우저에만 저장됩니다.
- 접수내용 등 자유 텍스트는 **개인정보 마스킹 후** 전송됩니다(전화·이메일·인명 호칭).
- 분석 규칙(작성 규칙·중대하자 의심 추출 키워드·장문 기준)은 `app.js`의 레지스트리
  (`RULE_DEF`·`CRIT_DEF`)에 고정되어 있습니다. 바꾸려면 코드를 수정해 배포합니다.
  형식 규칙(HTML·JSON 출력 구조)은 화면 렌더와 맞물려 있으므로 내용 규칙 위주로만 손댑니다.
- 중대하자는 **규칙이 후보를 넓게 뽑고 AI가 사내 매뉴얼 기준으로 최종 판단**하는 2단 구조입니다.

## 9. 스냅샷 내보내기

설정 > 스냅샷 > **내보내기**로 HTML 파일 1개를 받습니다.

- 기준 데이터는 **사내 게시본**입니다 — 팀원이 실제로 보는 집계·목록을 재계산 없이 담으므로
  어느 PC에서 만들어도 내용이 같습니다.
- 편집 모드에서 눌러도 게시본을 **조회만** 하므로 화면 모드는 그대로 유지됩니다
  (뷰어 시점에서 뽑으면 그 상태 유지).
- 네트워크가 안 되거나 아직 게시된 집계가 없으면 그 PC의 로컬 데이터로 만들고 토스트로 알립니다.
- **여러 달을 한 파일에 담을 수 있습니다.** 게시된 달이 둘 이상이면 내보낼 때 포함할 기준월을
  고르는 창이 뜹니다. 두 달 이상 고르면 파일 안에서 **뷰어처럼 기준월을 바꿔가며** 볼 수 있고,
  한 달만 고르면 그 달만 담긴 파일이 됩니다. 담은 달 수만큼 파일이 커지니 필요한 달만 고르세요.
- 파일은 게시본과 같은 정보량을 압축해 담은 단일 파일이며(월당 수백 KB~수 MB), 로그인 없이 열립니다.
  차트·압축 해제 라이브러리는 CDN에서 받으므로 **열 때 인터넷 연결이 필요**합니다.
- 설정의 **「스냅샷에 글꼴 포함」**을 켜면 본문 글꼴을 파일에 심어 어느 PC에서 열어도 화면과 같은
  모양이 됩니다(파일이 약 1.5MB 커집니다). 꺼두면 그 PC의 기본 한글 글꼴로 표시됩니다.

## 10. 구조와 데이터 흐름 (운영·개발)

```
HCS 엑셀 다운로드
   │  (편집자가 업로드)
   ▼
편집자 브라우저 IndexedDB  ←── 원본 하자 행은 여기에만 저장된다
   │  (calc: 기준월 말일 기준 집계)
   ▼
[게시] Firebase RTDB  report/{YYYY-MM}
   │  집계 KPI + 전체 미처리 목록(LZ 압축, PII 마스킹) + 주차/월별 캡처
   ▼
팀원 — 게시본을 실시간 구독해 열람
```

**핵심 사실 세 가지**

1. **원본 데이터는 서버에 없다.** 하자 행 원본은 업로드한 PC의 브라우저(IndexedDB)에만 있습니다.
   서버에는 월별 게시본(집계 + 마스킹된 목록)만 올라갑니다. 따라서 **업로드·게시하는 마스터 PC는
   한 대로 고정**하고, 그 PC의 브라우저 데이터를 함부로 지우면 안 됩니다.
2. **편집자 화면 = 로컬 계산, 팀원 화면 = 게시본.** 편집자가 다른 PC에서 로그인하면 그 PC의
   로컬 원본(없거나 구버전)으로 그려집니다. 게시된 그대로 보려면 설정 > 「뷰어 시점으로 보기」.
3. **기준월이 모든 계산의 축이다.** 지연일·장기미처리·누계는 전부 기준월 말일 기준입니다.

### 파일 구성

| 파일 | 역할 |
|---|---|
| `index.html` | 마크업 + CSS (인라인 스크립트 없음) |
| `app.js` | 앱 로직 전체 — `index.html` 하단에서 로드 |
| `xlsx.full.min.js` | SheetJS 0.20.x 자체 호스팅본. 없으면 CDN 0.18.5로 폴백 |
| `database.rules` | RTDB 보안 규칙(주석에 설계 의도·수용 리스크 문서화) |
| `README.md` | 이 문서 — 앱의 `?` 버튼(사용 안내)에서 그대로 렌더 |
| `docs/guide-*.png` | 사용 안내에 들어가는 화면 안내 이미지 |
| `PretendardVariable.woff2` | 본문 글꼴(자체 호스팅) |

아이콘은 **Lucide(ISC)** 아이콘을 `index.html` 안에 SVG 심볼 스프라이트로 인라인해 두고
`<svg class="icn"><use href="#i-…"></svg>` 로 씁니다. 크기·굵기는 `.icn` 한 곳에서만 정합니다.
**외부 아이콘 파일이나 CDN 아이콘 폰트로 바꾸면 스냅샷(단일 파일)에서 아이콘이 사라집니다.**
(`.ic` 는 주요 이슈 카드 클래스로 이미 쓰이므로 아이콘 클래스는 `.icn` 입니다.)

앱 로직은 외부 파일 `app.js`에 있고 CSP `script-src 'self'`로 허용됩니다.
`index.html`과 `app.js`는 항상 **같은 커밋으로 함께 배포**하세요(배포 직후엔 `Ctrl+F5`).
외부 스크립트는 jsdelivr + SRI 고정입니다. SheetJS는 저장소 파일을 우선 로드하고 없으면 CDN으로
폴백하는데, **폴백 경로가 살아 있는 동안 `readWorkbookSafe`의 프로토타입 오염 완화 코드는 제거 금지.**

## 11. 수정 → 검증 → 배포

1. 수정은 외과적으로 — 대규모 리라이트 금지, 기존 주석·설계 의도 보존.
2. 구문 검증(`node --check` 또는 브라우저 콘솔).
3. 브라우저에서 `index.html?selftest=1` → 자체 점검 전체 통과 확인.
4. git push → GitHub Pages 반영(캐시로 수 분 소요 가능 · `Ctrl+F5`).
5. **계산 로직을 바꿨다면 재게시**해야 팀원 화면에 반영됩니다.
6. 인터랙션을 바꿨다면 실제 브라우저에서 그 화면을 반드시 열어볼 것 — 정적 검사로 안 잡히는
   런타임 오류 이력이 있습니다(가능하면 Playwright 자동화).

### Firebase 운영

```bash
firebase deploy --only database                                                       # 규칙 배포
firebase emulators:exec --only database "node --test tests/database.rules.test.mjs"   # 규칙 테스트
```

- RTDB 최상위 노드: `users` · `report/{YYYY-MM}` · `reportIndex`(게시월→게시시각) ·
  `plans`(처리계획) · `analysis`(분석 의견) · `meta` · `siteConfig`. 스키마 외 키는 규칙이 거부합니다.
- `plans`·`analysis`는 편집자와 열람자 모두 쓰기 가능(협업), 나머지 쓰기는 편집자 전용입니다.
- App Check(reCAPTCHA Enterprise) 사용 중. CSP `script-src`의 Google 계열 호스트
  (`www.google.com`, `www.gstatic.com`, `www.recaptcha.net`, `recaptcha.google.com`,
  `apis.google.com`)가 하나라도 막히면 토큰 재시도 루프로 진입이 멈춥니다.
- 사용자 관리는 설정 > 계정 관리에서. 콘솔 직접 수정은 최초 부트스트랩 때만.

## 12. 문제 해결

| 증상 | 원인 | 조치 |
|---|---|---|
| 접속 시 로딩에서 멈춤 + 콘솔 CSP 차단 | `app.js` 미배포 또는 reCAPTCHA 호스트 차단 | 콘솔의 차단 URL 확인 → `app.js` 배포 여부·`script-src` 호스트 확인(20초 후 안내 워치독 있음) |
| 팀원 화면의 숫자·기준월이 이상함 | 잘못된 월의 구게시본 잔존 | 올바른 기준월로 재게시 → 미래 게시월 삭제 토스트에서 삭제 |
| 목록이 일부만 표시된다는 안내 | 전체 목록(압축) 도입 이전의 구게시본 | 최신 빌드에서 재게시 |
| 다른 PC에서 게시 내용이 안 보임 | 편집자 화면은 로컬 원본 기준(설계상 정상) | 설정 > 뷰어 시점으로 보기 |
| AI 분석 버튼이 안 먹음 | Gemini API 키 미입력 | 설정 > AI 분석에 키 입력(개인 키) |
| AI 분석 결과 표시가 깨짐 | 코드에서 형식 규칙(HTML·JSON 출력)을 잘못 수정 | `app.js` `RULE_DEF`의 형식 규칙(fmt 그룹) 원복 후 재생성 |
| 엑셀 업로드가 조용히 어긋남 | HCS 컬럼명 변경 | 업로드 요약과 원본 대조 · 컬럼 매핑 수정(개발 작업) |
| 사용 안내가 안 열림 | `README.md` 미배포 | 저장소 루트에 `README.md` 커밋 확인 |
| 스냅샷이 빈 화면·로그인 화면으로 뜸 | 인라인 앱 스크립트가 CSP 해시와 불일치 | 파일 내 인라인 스크립트 해시와 meta CSP 해시 대조 → 재생성 |

## 13. 하지 말아야 할 것

- **마스터 PC의 브라우저 데이터(IndexedDB) 삭제 금지** — 원본 하자 행이 사라집니다.
  삭제·PC 교체 전 HCS 원본 엑셀 보관과 스냅샷 백업을 확인하세요. 앱이 부팅 시
  `navigator.storage.persist()`로 영속화를 요청하지만 이것이 백업을 대체하지는 않습니다 —
  **월별 원본 엑셀은 별도 보관이 원칙.**
- `index.html`만 또는 `app.js`만 단독 배포 금지 — 두 파일은 항상 같은 커밋으로.
- `database.rules` 스키마를 앱 수정 없이 단독 변경 금지 — 앱의 저장 구조와 맞물려 있습니다.
- 게시 목록의 PII 마스킹 제거 금지 — 입주민 개인정보가 전 팀원에게 노출됩니다.
- 아이콘을 외부 스프라이트 파일·CDN 아이콘 폰트로 이전 금지 — 스냅샷은 `index.html`과 `app.js`만
  담으므로 외부 리소스는 그 안에서 깨집니다.
- **형식 규칙(OUTPUT FORMAT — HTML·JSON 출력) 수정 금지** — 화면 렌더와 결합되어 있습니다.
  형식이 깨졌다면 즉시 기본값으로 복원하세요.
